The problem

Projects die in the gap between sessions.

Without a system

  • You spend 20 minutes rebuilding context every morning.
  • Half-finished thoughts live in Slack DMs and never resurface.
  • The "why" of an old decision is lost by sprint three.
  • Your cloud infra keeps burning money because you forgot to shut it down.
  • Every project reinvents its own ad-hoc PM structure.

With ds-work

  • /ds-work-continue rebuilds context in one command.
  • /ds-work-backlog add captures the thought in two seconds.
  • Decisions live in a Decision Log at the bottom of the doc that owns them.
  • /ds-work-halt runs project-specific teardown — scale nodes to zero, stop Postgres, commit, push.
  • Every project uses the same mental model: one question, one document.
Two modes

Start lite. Graduate when you need to.

Not every project needs a vision document. Pick the shape that fits — the plugin behaves differently in each mode.

lite

For scripts, tools, and clear execution paths

A stripped-down stack: milestones.md is the plan. No vision, no roadmap, no PRDs. Four files total.

  • milestones.md — all milestones + tasks in one file
  • parking-lot.md — unscheduled work
  • backlog.md — mind-dump
  • recurring.md — tasks that decay
full

For real products with stakeholders

The complete stack: vision, roadmap, per-milestone PRDs and PLANs, challenge reviews, market research, communications artifacts.

  • Everything in lite, plus:
  • vision.md, roadmap.md, now.md
  • design/M{N}-PRD.md + M{N}-PLAN.md
  • reviews/ — adversarial challenge reports
  • one-pager.md, elevator-pitch.md, ICP

Promote with /ds-work-graduate — one-way, additive, existing files preserved.

The command map

20 commands, four phases.

Setup → Plan → Work → Review. Every command reads existing state and does the smallest useful thing.

01 Setup

/ds-work-scaffold

Bootstrap product/ with placeholder docs. Asks lite or full mode.

/ds-work-graduate

Promote a lite-mode project to full. Additive, one-way.

/ds-work-vision

Interactively write or review vision.md. full

/ds-work-roadmap

Interactively write or review roadmap.md. full

02 Milestone planning

/ds-work-plan

State-driven: writes M{N}-PRD.md and M{N}-PLAN.md, or runs a drift review if both exist. full

03 Session lifecycle

/ds-work-continue

Start of session. Resume brief: active milestone, sub-state, next task.

/ds-work-status

Mid-session. The next concrete action — shorter than continue.

/ds-work-update

Checkpoint snapshot appended to today's session report.

/ds-work-halt

End of session. Updates docs, commits, pushes, runs project-specific teardown.

/ds-work-parking-lot

Manage unscheduled items. add, pick, filter by tag.

/ds-work-backlog

Low-commitment mind-dump. One rung below parking lot.

/ds-work-recurring

Tasks that decay — refresh a snapshot, re-validate a pin, sweep a dir.

04 Review, research, communication

/ds-work-challenge

Adversarial pressure-test of a planning artifact. full

/ds-work-research

Structured market, competitive, or technology deep-dives.

/ds-work-spike

Time-boxed technical spike with a single yes/no question.

/ds-work-one-pager

Generate one-pager.md (~500 words). full

/ds-work-elevator-pitch

Three pitch variants: tweet, 30s verbal, 60s investor. full

/ds-work-ideal-customer-profile

Interactively develop an ICP — firmographics, triggers, PMF signals. full

/ds-work-user-guide

Print the full guide inline, optionally save a copy into your project.

Mental model

One question, one document.

The moment the same content lives in two places, they drift. Every stable question gets exactly one home under product/.

Customize without forking

Project-specific extensions via how-to/.

Drop a file at product/how-to/ds-work-<command>.md and that command folds in your steps. The generic behavior stays in the plugin.

Example: shut down cloud infra every time you halt a session.
# product/how-to/ds-work-halt.md

After committing and pushing, also:

1. Scale GPU pool to 0:
   `kubectl scale --replicas=0 deployment/inference -n prod`
2. Stop Postgres:
   `gcloud sql instances patch my-db --activation-policy=NEVER`
3. Stop local docker:
   `docker compose -f infra/local/docker-compose.yml stop`
4. Confirm everything is down, then report.

Next time you run /ds-work-halt, Claude reads this file and runs those steps as part of shutdown. You don't even need to write the file by hand — just ask Claude to customize the command for your project.
