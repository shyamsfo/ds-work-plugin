Walkthrough · ~8 min read

From empty directory
to shipped milestone.

You'll build linkjar, a tiny bookmark API in Python/FastAPI, using ds-work end-to-end. Every terminal block below is what the plugin actually prints — no marketing fiction. Lite mode throughout.

The ten steps
  1. Start with an idea in a text file
  2. Scaffold the project
  3. Turn the idea into milestones
  4. Resume into the first task
  5. Checkpoint mid-flow
  6. Park a drifting thought
  7. Wrap the session cleanly
  8. Come back the next day
  9. Stay oriented mid-flow
  10. Finish the last milestone
01

Start with an idea in a text file.

You've been meaning to build this for months — a tiny bookmark API, one process, something you'd actually use instead of the thirty tabs rotting in your browser. You start with a fresh directory and a napkin brief. No README, no plan — just enough to point Claude at.

~/code/linkjar/idea.txt
linkjar: a bookmark API I actually want to use.

- POST /bookmarks     save a URL with optional title + tags
- GET  /bookmarks     list, filter by tag, search by text
- DELETE /bookmarks/{id}

- API-key auth, one user for now (me)
- FastAPI + sqlite via SQLAlchemy
- single process, no celery, no redis
- deploy by running: uvicorn linkjar.main:app

Now open Claude Code in the empty directory.

$ mkdir linkjar && cd linkjar
$ $EDITOR idea.txt   # paste the brief above
$ claude
02

Scaffold the project.

Run /ds-work-scaffold. It asks one question before touching anything.

claude code — linkjar 
> /ds-work-scaffold

This will scaffold a new project. Pick a mode:

  1. full — vision.md, roadmap.md, now.md, per-milestone PRDs + PLANs,
            design reviews, market research. Best for projects with real
            product framing or external stakeholders.

  2. lite — milestones.md (with all milestones in one file), backlog.md,
            parking-lot.md, recurring.md, reports/. No vision, no roadmap,
            no PRDs. Best for projects with a clear execution path.

Which mode? (full / lite, default: full)

> lite

Creating product/ (lite mode)…
  ✓ product/ds-work-mode.txt      (contains: lite)
  ✓ product/milestones.md
  ✓ product/backlog.md
  ✓ product/parking-lot.md
  ✓ product/recurring.md
  ✓ product/how-to/
  ✓ product/reports/
  ✓ product/project-management-principles.md

Done. milestones.md is empty — want me to seed it from idea.txt?
Why lite

linkjar is a scope you can hold in your head: four features, one process, one developer. Lite mode skips vision/roadmap/PRDs — milestones.md is the plan. If this ever grows stakeholders or a billing system, /ds-work-graduate promotes to full mode without rewriting anything.

03

Turn the idea into milestones.

Rather than hand-writing milestones.md, point Claude at idea.txt and let it propose a milestone breakdown. You push back where you disagree — this is a conversation, not a one-shot.

claude code — linkjar 
> yes — read idea.txt and propose milestones

Reading idea.txt…

Proposed milestones:

M1 — scaffold + health endpoint
   [ ] pyproject.toml with fastapi, sqlalchemy, uvicorn deps
   [ ] src/linkjar/main.py: FastAPI app + GET /healthz
   [ ] README quickstart: install + run instructions

M2 — CRUD bookmarks
   [ ] SQLAlchemy model: id, url, title, created_at
   [ ] POST, GET (list + by id), DELETE /bookmarks
   [ ] alembic migration for the bookmarks table
   [ ] tests: 4 endpoint tests covering happy paths

M3 — API-key auth
   [ ] key in X-API-Key header, loaded from LINKJAR_API_KEY env
   [ ] FastAPI dependency applied to all /bookmarks routes
   [ ] /healthz stays public; everything else 401 without the key
   [ ] tests: 401 without key, 200 with correct key

M4 — tags + search
   [ ] tags column (comma-joined for now)
   [ ] GET /bookmarks?tag=x and ?q=foo (LIKE over title)
   [ ] tests: filter by tag, search by text

Sound right? I'll write them into milestones.md and mark M1 🔄 in progress.

> yes

Wrote product/milestones.md. M1 is 🔄 in progress; M2–M4 are ⏳ queued.

Four milestones, each with 3–4 small tasks. No fluff, no "research spike" phases, no "project setup" meta-tasks. Each task names a concrete artifact you'll produce.

04

Resume into the first task.

Even on a fresh project, /ds-work-continue is worth running. It reads milestones.md, inspects git log and git status, and tells you exactly where to pick up. One less decision in the morning — same command every session.

claude code — linkjar 
> /ds-work-continue

Reading product/ds-work-mode.txt… lite
Reading product/milestones.md…
git log --oneline -8… no commits yet
git status… idea.txt untracked, product/ untracked

## Resume Brief

Milestone: M1 — scaffold + health endpoint
Progress:  0 / 3 tasks ticked
Next task: pyproject.toml with fastapi, sqlalchemy, uvicorn deps
Blockers:  none — fresh project, no commits yet
Parking:   0 open items

Shall I draft pyproject.toml?

> yes, go

Claude writes pyproject.toml, generates src/linkjar/main.py with the /healthz endpoint, and you boot the server with uvicorn to confirm it works. Standard loop. The plugin isn't doing the coding — it's holding the state between the coding sessions.

05

Checkpoint mid-flow.

You've been heads-down for an hour. Two tasks done, a decision made along the way (single-package src/ layout). Run /ds-work-update to drop a timestamped snapshot into today's session report. It doesn't commit, doesn't halt — just records what's happened so far.

claude code — linkjar 
> /ds-work-update

Appending to product/reports/2026-10-09.md…

### 11:14 checkpoint
- M1 task 1 ✓ pyproject.toml with fastapi, sqlalchemy, uvicorn
- M1 task 2 ✓ src/linkjar/main.py with /healthz returning {"status":"ok"}
- M1 task 3 pending: README quickstart
- Decision: single-package src/ layout (no monorepo). Easier packaging later.
- Next: draft README, then move to M2 — CRUD bookmarks.

✓ Snapshot written. No commit, no halt — keep going.
Why bother

Future-you reading reports/2026-10-09.md next week sees not just what you did but why. The "Decision" line costs five seconds now and saves fifteen minutes of "wait, why did we not use a monorepo again?" later.

06

Park a drifting thought.

Mid-task, a thought drifts in: sqlite is fine now, but I'll want Postgres before this leaves my laptop. You don't want to context-switch into infra planning. Park it.

claude code — linkjar 
> /ds-work-parking-lot add "swap sqlite for Postgres before deploying anywhere real"

Appending to product/parking-lot.md under ## Open (newest at top)…
✓ Parked. Back to M1 task 3.

Two seconds. No ticket, no Slack message, no Notion page. The thought is captured somewhere you'll actually look at it — /ds-work-continue surfaces open parking-lot items in the resume brief.

07

Wrap the session cleanly.

You've finished M1. Run /ds-work-halt. It's not just git commit && git push — it ticks the milestone, writes the final session report, sweeps parking-lot/recurring, and asks if there's anything left to capture before committing. Half of why the plugin exists is that this moment is always the one you skip when you're tired.

claude code — linkjar 
> /ds-work-halt

Reading milestones.md, git log, git status…

Anything that came up this session worth parking? (one line per item, or skip)
> skip   # already parked the Postgres one

M1 progress: 3 / 3 tasks complete — milestone done.
  ✓ Flipping M1 → ✓ in milestones.md
  ✓ Setting M2 → 🔄 in progress

Writing product/reports/2026-10-09.md…
  ✓ Final session summary appended (M1 shipped)

Committing src/, pyproject.toml, README.md, product/…
  ✓ 7 files, 243 insertions
  ✓ Pushed to origin/main

Session wrapped. Tomorrow's /ds-work-continue picks up at M2 — CRUD bookmarks.
Project-specific halt steps

Drop a product/how-to/ds-work-halt.md in your repo and /ds-work-halt will fold its steps in. For linkjar it's nothing special, but if you were paying for a GPU pool, you'd put "scale deployment to 0" in there and never forget again.

09

Stay oriented mid-flow.

You've been heads-down for 90 minutes on M2. Model written, POST and GET working, you glance up and lose the thread for ten seconds — what was I about to do. Run /ds-work-status. It's /ds-work-continue's little sibling: no preamble, just the next move and how to verify it.

claude code — linkjar 
> /ds-work-status

M2 (lite) · 2 / 4 ticked

Next:   alembic migration for the bookmarks table
File:   alembic/versions/0001_bookmarks.py
Verify: alembic upgrade head creates the table;
         pytest tests/test_bookmarks.py passes

Four lines. Enough to get back to typing without re-reading milestones.md.

That's the loop.

Six commands, used repeatedly. scaffold once. Then continue / update / halt daily, parking-lot when a thought drifts in, status when you lose the thread. The other fourteen commands exist for the day you need them — writing a vision doc, adversarially reviewing a plan, drafting a one-pager. For most projects, the six above are all you'll touch.

Nothing in this walkthrough was fabricated for the demo. Every terminal block mirrors what the commands actually print, down to the resume brief format and the halt sequence. Try it on a project that's been drifting — /ds-work-scaffold --lite in the project root, then ask Claude to seed milestones.md from whatever brief you already have.
